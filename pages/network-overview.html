0全局视角:先看清整张网

整个计算机网络只回答一个问题:两台不直接相连的主机上的两个进程,如何可靠、高效地交换数据。这个问题太大,于是被垂直切成五层,每层解决一个子问题、并只依赖下一层提供的服务:

层解决的核心问题传输单位典型协议/设备寻址
应用层App进程之间按什么格式、什么规则对话报文 messageHTTP、DNS、SMTP域名 / URL
传输层Transport把「主机到主机」提升为「进程到进程」,并可选地提供可靠性报文段 segmentTCP、UDP端口号
网络层Network跨越多个网络,把分组从源主机送到目的主机(选路 + 转发)数据报 datagramIP、ICMP;路由器IP 地址
链路层Link在一段直接相连的链路/局域网内把帧交给相邻结点帧 frame以太网、Wi‑Fi、ARP;交换机MAC 地址
物理层Physical把比特变成电/光/电磁信号在介质上传输比特 bit双绞线、光纤;集线器—

记住这条寻址链,它就是全书的主线:域名 →(DNS)→ IP 地址 + 端口号 →(路由)→ 每一跳的下一站 IP →(ARP)→ MAC 地址 →(链路)→ 比特流。上层地址逐级翻译为下层地址,数据逐级封装。

0.1 电路交换 vs 分组交换

  • 电路交换(电话网):通信前先建立端到端专用通路,预留固定带宽(FDM 频分 / TDM 时分)。优点是时延确定、无排队;缺点是空闲时段带宽浪费、建立连接慢。
  • 分组交换(互联网):数据切成分组,每个分组带目的地址,路由器存储—转发,按需共享链路(统计复用)。优点是链路利用率高、容错好;代价是排队时延和丢包——路由器缓存有限,突发流量超过输出链路速率时分组排队,队满则丢弃。
  • 互联网选择分组交换,因为数据业务是突发的:大多数用户大多数时间不发数据,统计复用能让远多于「带宽÷人均速率」的用户共享同一条链路。

0.2 四种时延 + 两个性能指标(必考计算)

一个分组经过一台路由器的总时延 = 处理时延 + 排队时延 + 传输时延 + 传播时延:

  • 处理时延:检查首部、查表决定出口,微秒级,通常忽略。
  • 排队时延:在输出队列等待,取决于拥塞程度,是唯一不确定的一项。流量强度 La/R(a 为分组到达率,L 为分组长度,R 为链路速率)趋近 1 时排队时延急剧增大,大于 1 则队列无限增长。
  • 传输时延 = L / R:把整个分组的比特「推上链路」所需时间,取决于分组长度和链路带宽,与距离无关。
  • 传播时延 = d / s:信号跑完链路长度 d 所需时间(s ≈ 2×10⁸ m/s,铜线光纤都按此量级),取决于距离,与分组长度无关。
易混警告 传输时延和传播时延是最经典的混淆点:传输时延是「上车时间」(与 L、R 有关),传播时延是「行车时间」(与 d 有关)。存储—转发意味着每一跳都要重新付一次传输时延:经过 N 段速率为 R 的链路发送一个分组,总时延 = N·L/R(忽略传播与排队)。
  • 吞吐量:端到端路径的实际数据传输速率,受制于路径上的瓶颈链路(min 各段速率)。传输 F 比特文件的时间 ≈ F / 瓶颈速率。
  • 时延带宽积 = 传播时延 × 带宽,表示链路上「正在飞行」的比特数,是理解滑动窗口大小的关键。

1应用层:进程如何对话Application

应用层协议规定报文的类型、语法、字段语义和收发时序。它运行在端系统上,把下面所有层当作一条「进程到进程的管道」使用——这个管道的接口就是套接字 socket。应用层要做的第一个决定是选传输服务:要可靠字节流选 TCP,要低时延、能容忍丢包选 UDP。

1.1 两种应用架构

  • 客户—服务器 C/S:服务器常开、有固定 IP,客户主动发起请求,客户之间不直接通信。扩展靠数据中心堆机器。
  • P2P:对等方之间直接通信,每个结点既是客户又是服务器,具有自扩展性——新用户带来需求也带来上传能力。典型:BitTorrent(最稀缺优先下载、对上传贡献大的邻居优先回报)。分发 F 比特文件给 N 个用户,C/S 时间随 N 线性增长,P2P 时间趋于常数级,这是经典分析题。

1.2 HTTP:Web 的应用层协议

  • 基于 TCP,端口 80(HTTPS 443)。协议本身无状态:服务器不保存历史请求信息;状态由 Cookie 补上——服务器用 Set-Cookie 发标识,浏览器此后每次请求带 Cookie 头,服务器据此在后端数据库关联用户。
  • 非持续 vs 持续连接:HTTP/1.0 每个对象新建一次 TCP 连接,取一个对象耗时 ≈ 2 RTT + 传输时间(1 RTT 握手 + 1 RTT 请求响应);HTTP/1.1 默认持续连接,多个对象复用同一 TCP 连接,可流水线发送请求。
  • HTTP/2:同一 TCP 连接内多路复用多个流、帧交错发送,解决 1.1 的队首阻塞(HTTP 层),支持服务器推送、首部压缩。但 TCP 层丢包仍会阻塞所有流,于是 HTTP/3 改用基于 UDP 的 QUIC,把可靠传输、加密、多路复用做到用户态,流之间互不阻塞。
  • 报文格式:请求 = 请求行(方法 URL 版本)+ 首部行 + 空行 + 实体体;响应 = 状态行(版本 状态码 短语)+ 首部行 + 空行 + 实体体。首部是纯文本、以 CRLF 分行。
  • 方法:GET(获取,参数在 URL)、POST(提交,数据在实体体)、HEAD(只要响应首部)、PUT(上传/整体替换)、DELETE。
状态码含义说明

1.3 DNS:域名系统

DNS 是「用应用层协议实现的核心基础设施」:把域名翻译成 IP,同时提供主机别名、邮件服务器别名、负载均衡。运行在 UDP 端口 53(响应超长或区域传送用 TCP)。

  • 层次结构:根服务器(13 组)→ 顶级域 TLD 服务器(.com、.cn)→ 权威服务器(存放具体域的记录)。另有不在层次里的本地 DNS 服务器,由 ISP/校园网提供,是主机的直接代理。
  • 查询过程(标准考题):主机 → 本地 DNS 为递归查询(全权代办);本地 DNS → 根 → TLD → 权威通常为迭代查询(每问一级,对方只告诉「下一个该问谁」)。结果沿途缓存(按 TTL 过期),所以绝大多数查询根本到不了根服务器。
  • 资源记录 RR = (Name, Value, Type, TTL):
类型Name → Value用途
A / AAAA主机名 → IPv4 / IPv6 地址最基本的解析
NS域 → 该域权威服务器的主机名沿层次向下引路
CNAME别名 → 规范主机名一个站点多个名字
MX域 → 邮件服务器规范名投递邮件前查询

1.4 电子邮件

  • 三个组成:用户代理、邮件服务器、协议。发送方向:用户代理 →(SMTP)→ 发方服务器 →(SMTP)→ 收方服务器;拉取方向:收方用户代理用 POP3(110)或 IMAP(143) 从自己的服务器取信,或直接用 Web 界面(HTTP)。
  • SMTP,TCP 端口 25:推协议(连接由发送方发起),只传 7 位 ASCII,二进制附件靠 MIME 编码(Base64)。与 HTTP 对比:HTTP 是拉协议、每个对象独立封装;SMTP 是推协议、多个对象合成一个报文。
  • POP3 简单、邮件状态只在本地;IMAP 在服务器端保存文件夹状态,多设备同步,是现代默认。

1.5 视频流与 CDN

  • DASH(基于 HTTP 的动态自适应流):视频编码成多个码率版本、切成小块,客户端按当前测得带宽逐块选择码率请求——智能在客户端。
  • CDN:把内容副本部署到全球边缘节点,用户请求被 DNS 重定向到「最近」的副本服务器(权威 DNS 返回 CNAME 指向 CDN,CDN 的 DNS 根据本地 DNS 的位置选节点)。解决单源站的距离时延、单点故障与出口带宽瓶颈。
本层小结 应用层输出一段报文和一个目标 IP:端口(IP 由 DNS 得到),通过 socket 交给传输层。它对「报文如何可靠到达」一无所知——这正是下一层的工作。

2传输层:进程到进程,以及可靠性Transport

网络层只负责「主机到主机」的尽力而为交付——会丢包、会乱序、不保证时延。传输层在此之上做两件事:① 复用/分用,用端口号把数据送到正确的进程;② 可选地把不可靠信道升级为可靠信道(TCP)。

2.1 复用与分用

  • UDP 分用用二元组(目的 IP,目的端口)定位 socket;TCP 分用用四元组(源 IP,源端口,目的 IP,目的端口)——所以同一服务器端口 80 可以同时服务大量连接,每条连接各有 socket。
  • 周知端口 0–1023,注册端口 1024–49151,客户端临时端口通常取 49152–65535。

2.2 UDP:几乎裸的 IP

  • 只做分用 + 差错检测。无连接、无握手、不保证交付与顺序、无拥塞控制。首部仅 8 字节:源端口、目的端口、长度、校验和(各 2 字节)。
  • 校验和:把伪首部 + 首部 + 数据按 16 位字反码求和再取反;接收方全加起来应为全 1。能检错,不能纠错。
  • 选 UDP 的理由:无建连时延(DNS)、无连接状态服务器可支撑更多客户、首部开销小、发送速率完全由应用控制(实时音视频宁丢不等)。QUIC 则证明可以在 UDP 上重建可靠性。

2.3 可靠数据传输原理(rdt):从停等到滑动窗口

这是传输层的理论核心,考试爱考。问题:信道会出错和丢包,如何在其上实现可靠传输?机制逐步叠加:

  • 应对比特错:校验和检错 + 接收方反馈 ACK/NAK + 出错重传(ARQ)。ACK 本身也可能坏 → 引入序号让接收方识别重复分组(停等只需 0/1 交替)。
  • 应对丢包:发送方设倒计时定时器,超时重传。重复分组由序号去重,所以重传永远是安全的。
  • 停等协议的致命伤是利用率:U = (L/R) / (RTT + L/R)。长肥链路上(RTT 大)利用率极低 → 引入流水线:不等确认连续发送多个分组,需要更大的序号空间和缓存,由「窗口」管理。
回退 N 步 GBN选择重传 SR
发送窗口≤ 2ᵏ − 1(k 为序号位数)≤ 2ᵏ⁻¹
接收窗口1(只按序收)与发送窗口同,可缓存失序分组
确认方式累积确认:ACK n 表示 ≤ n 全部收到逐个确认
超时重传重传窗口内全部未确认分组(一个定时器)只重传超时的那一个(每分组一个定时器)

窗口上限为什么不同 GBN 若窗口 = 2ᵏ,接收方无法区分「全部 ACK 丢失后的重传 0 号」与「新一轮的 0 号」;SR 因接收窗口也很大,新旧窗口的序号不能有任何重叠,故上限减半为 2ᵏ⁻¹。

2.4 TCP:面向连接的可靠字节流

TCP 提供点对点、全双工、面向连接的可靠字节流——「字节流」意味着 TCP 不保留应用报文边界,序号编在字节上而不是报文段上。它综合了 GBN 与 SR:累积确认像 GBN,但接收方一般缓存失序段、且只重传疑似丢失的那个段,像 SR。

连接建立:三次握手

客户 → 服务器:SYN, seq = x→ 服务器 → 客户:SYN + ACK, seq = y, ack = x+1→ 客户 → 服务器:ACK, seq = x+1, ack = y+1(可携带数据)
  • SYN 和 FIN 各消耗一个序号;初始序号随机以防旧连接的报文串扰。
  • 为什么是三次而不是两次:两次握手时,网络中滞留的旧 SYN 到达服务器会被当作新连接请求,服务器单方面建立连接并空等,造成资源浪费;第三次 ACK 让服务器确认客户方确实在场且双方序号同步。
  • SYN 洪泛攻击利用半连接队列耗尽服务器资源,防御用 SYN cookie(服务器不保存状态,把状态编码进 y)。

连接释放:四次挥手

主动方:FIN→ 被动方:ACK→ 被动方(数据发完后):FIN→ 主动方:ACK,进入 TIME_WAIT
  • 之所以四次:关闭是双向独立的,被动方收到 FIN 后可能还有数据要发,ACK 与它自己的 FIN 不能合并(除非恰好无数据,可合并成三次)。
  • TIME_WAIT 等待 2MSL(报文最大生存时间的两倍)的原因:① 确保最后一个 ACK 若丢失,还能应答对方重传的 FIN;② 让本连接的所有旧报文在网络中死光,防止污染下一个相同四元组的连接。

超时与重传

  • RTT 估计(指数加权移动平均):EstimatedRTT = 0.875·EstimatedRTT + 0.125·SampleRTT;偏差 DevRTT = 0.75·DevRTT + 0.25·|Sample − Estimated|;TimeoutInterval = EstimatedRTT + 4·DevRTT。每次超时后间隔加倍(指数退避)。重传的段不采样 RTT(Karn 算法),避免二义性。
  • 快重传:收到 3 个冗余 ACK(同一确认号第 4 次出现)即判定该段丢失,不等超时立刻重传。
  • 接收方采用延迟 ACK:收到按序段等 500 ms 内若有第二个段则发一个累积 ACK;收到失序段立即发冗余 ACK。

流量控制 vs 拥塞控制

  • 流量控制防止压垮接收方:接收方在首部 rwnd 字段通告剩余缓存,发送方保证未确认字节数 ≤ rwnd。rwnd = 0 时发送方仍发 1 字节探测段,避免死锁。
  • 拥塞控制防止压垮网络:维护拥塞窗口 cwnd,实际发送窗口 = min(cwnd, rwnd)。网络不会明确报告拥塞,TCP 把丢包(超时或 3 冗余 ACK)当作拥塞信号。

拥塞控制算法(Reno,必考)

  • 慢启动:cwnd 从 1 MSS 起,每收到一个 ACK 加 1 MSS —— 每 RTT 翻倍(指数增长),直到达到阈值 ssthresh 转入拥塞避免。
  • 拥塞避免:每 RTT cwnd 加 1 MSS(线性增长,加性增 AI)。
  • 超时丢包(严重拥塞):ssthresh = cwnd/2,cwnd = 1,重新慢启动。
  • 3 冗余 ACK(轻度拥塞,网络还能送达包):快重传 + 快恢复:ssthresh = cwnd/2,cwnd = ssthresh,直接进入拥塞避免(乘性减 MD)。
  • 整体形成 AIMD 锯齿:加性增探测带宽,乘性减快速让出带宽。AIMD 使共享瓶颈的多条连接收敛到公平分享。现代变体:CUBIC(Linux 默认,窗口按三次函数增长)、BBR(基于测量带宽与 RTT,不依赖丢包信号)。
画图题模板 横轴 RTT、纵轴 cwnd:指数爬升(慢启动)→ 到 ssthresh 改直线(拥塞避免)→ 超时则跌回 1 重来 / 3 冗余 ACK 则腰斩后继续直线。给定初始 cwnd、ssthresh 和丢包时刻,逐 RTT 写出 cwnd 序列即可。
本层小结 传输层把应用报文切成段、编上字节序号、附上端口,交给网络层的只是一个个独立的段。它假设网络层能把段送到对端主机——至于怎么穿过几十个路由器,是网络层的事。

3网络层:把数据报送到目的主机Network

网络层是唯一「每台路由器都参与」的一层,分成两个平面:数据平面(转发 forwarding:单台路由器查表把分组从输入端口移到输出端口,纳秒级、硬件实现)和控制平面(路由 routing:全网协作算出转发表,秒级、软件实现)。IP 提供的服务模型是尽力而为:不保证交付、不保证顺序、不保证时延。

3.2 IPv4 编址与子网划分(最高频计算题)

  • IP 地址 32 位 = 网络前缀 + 主机号,记法 a.b.c.d/x(CIDR,前缀长度 x 任意,取代了僵硬的 A/B/C 分类)。子网掩码即前 x 位为 1 的 32 位数。
  • 子网内计算:主机号全 0 是网络地址、全 1 是广播地址,可用主机数 = 2(32−x) − 2。例:192.168.10.0/26 → 块大小 64,范围 .0–.63,可用 .1–.62,广播 .63。
  • 路由聚合:多个连续前缀合并成更短前缀对外通告(如 8 个 /24 聚合为一个 /21),缩小路由表。转发查表用最长前缀匹配:多条路由都匹配时选前缀最长(最具体)的那条。
  • 特殊地址:私有地址 10/8、172.16/12、192.168/16(不可在公网路由,需 NAT);环回 127.0.0.1;本网广播 255.255.255.255;DHCP 未获址时源地址用 0.0.0.0。

3.3 主机怎么拿到地址:DHCP

  • 即插即用的应用层协议,跑在 UDP,服务器 67 / 客户 68。四步(DORA):Discover(广播找服务器)→ Offer(服务器提供候选 IP)→ Request(客户广播选定)→ ACK(确认,附租期)。
  • 一次性发给主机四样东西:自己的 IP、子网掩码、默认网关(第一跳路由器)IP、本地 DNS 服务器 IP——这正是主机上网的全部初始配置。

3.4 NAT 与 ICMP

  • NAT:出方向把(私有 IP, 源端口)改写为(公网 IP, 新端口)并记入转换表,入方向反查改回。让一个公网 IP 背后挂整个内网,是 IPv4 地址枯竭的续命术。争议:改写端口号越层操作了传输层字段,破坏端到端原则,外部无法主动连入内网主机(P2P 需打洞/中继)。
  • ICMP:封装在 IP 数据报内的「网络层差错与查询信使」。常考类型:回显请求/应答(8/0,ping 用)、目的不可达(3,含端口不可达)、TTL 超时(11)。traceroute 原理:依次发 TTL=1,2,3… 的探测包,每台路由器在 TTL 减到 0 时回「超时」ICMP,其源地址即第 n 跳路由器;到达目的主机时因端口不可达返回类型 3,探测结束。

3.5 IPv6

  • 地址 128 位,冒号十六进制记法。首部定长 40 字节,删掉了校验和(交给传输层与链路层)、分片字段和选项(移入扩展首部),路由器处理更快;新增流标签。
  • 过渡技术:双栈(同时跑 v4/v6)、隧道(v6 报文整个装进 v4 报文穿越 v4 网络)、NAT64 转换。

3.7 层次路由:AS 内与 AS 间

互联网按自治系统 AS组织(一个 ISP/机构一个 AS),路由分两级——规模和管理自治都要求这么做:

  • AS 内(IGP)—— OSPF:链路状态协议,管理员配置链路权值,支持划分区域(area)进一步分层,直接封装在 IP 上。目标是性能最优。
  • AS 间 —— BGP:事实上的互联网粘合剂。路径向量协议,通告「前缀 + AS 路径 + 下一跳」等属性,AS 路径可检测环路;跑在 TCP 179 上,分 eBGP(跨 AS 学路由)与 iBGP(在 AS 内部传播)。选路策略优先于性能:本地偏好值最高者胜 → AS 路径最短 → 热土豆路由(选最快离开本 AS 的出口)。商业关系(客户/提供商/对等)决定通告策略,例如不为两个提供商免费转接流量。
  • SDN:把控制平面从路由器抽出集中到控制器,交换机只按控制器下发的「匹配 + 动作」流表转发(OpenFlow),使路由、防火墙、负载均衡都成为可编程软件。
本层小结 网络层把段装进数据报,靠路由协议算好的转发表逐跳接力,把数据报送到目的主机。但「下一跳」在物理上如何到达——同一局域网里怎么把帧精确递给邻居——是链路层的事。

4链路层:一段链路内的交付Link

链路层负责把数据报封装成帧,在一段链路或一个局域网内从一个结点递到相邻结点。它主要在网卡(适配器)中实现。三大主题:差错检测、多路访问(共享介质谁先说话)、以太网与交换机。

4.1 差错检测

  • 奇偶校验:1 位只能检奇数个错;二维奇偶可纠正 1 位错。
  • 校验和(传输层用):16 位反码和,软件实现快但检错弱。
  • CRC 循环冗余检验(链路层标准做法):选定 r+1 位生成多项式 G,在数据 D 后补 r 个 0,对 G 做模 2 除法(即异或),余数 R 作为 FCS 附在帧尾;接收方用 G 除整个 (D·2ʳ + R),余数为 0 即认为无错。能检出所有 ≤ r 位的突发错误。计算题:列竖式做异或除法,取 r 位余数。

4.2 多路访问协议:共享信道谁来用

  • 信道划分:TDM、FDM、CDMA——公平但低负载时浪费。
  • 轮流:轮询(主结点点名,有轮询开销和单点故障)、令牌传递。
  • 随机接入(重点):
    • 时隙 ALOHA:想发就在下一时隙发,碰撞则以概率 p 重试,最大效率 1/e ≈ 37%;纯 ALOHA 减半 ≈ 18%。
    • CSMA/CD(经典有线以太网):先听后发、边发边听,检测到碰撞立即停止并发拥塞信号,然后二进制指数退避——第 n 次碰撞后从 {0,1,…,2ᵐⁱⁿ⁽ⁿ,¹⁰⁾−1} 随机选 K,等 K·512 比特时间重试。
    • 碰撞检测要求「发完之前必须能听到碰撞」:帧的传输时延 ≥ 2τ(端到端往返传播时延,称争用期),由此导出以太网最小帧长 64 字节;这也是网络跨度与速率互相制约的原因。

4.3 MAC 地址与 ARP

  • MAC 地址:48 位,烧录在网卡,全球唯一,扁平结构(与位置无关);IP 地址层次化(与所在网络有关)。两者都需要:IP 用于跨网选路,MAC 用于本地链路交付,而且主机换网络时 IP 变、MAC 不变。全 1(FF-FF-FF-FF-FF-FF)是广播地址。
  • ARP:IP → MAC 的翻译。发送方在本子网广播 ARP 请求「谁是 x.x.x.x?」,目标主机单播应答自己的 MAC;结果缓存(带 TTL)。ARP 跨在网络层与链路层之间,即插即用。
  • 关键规则:目的主机不在本子网时,帧的目的 MAC 填默认网关的 MAC(通过 ARP 查网关 IP 得到),绝不可能直接填最终目的主机的 MAC。

4.5 交换机

  • 自学习:收到帧就把(源 MAC → 入端口)记入交换表;转发时查目的 MAC,查不到则向除入口外所有端口泛洪,查到则定向转发(目的与来源同端口则过滤丢弃)。即插即用,无需配置。

5物理层:比特与信号Physical

  • 任务:定义接口的机械/电气/功能特性,完成编码(如曼彻斯特、4B/5B)与调制(调幅/调频/调相、QAM),把比特流搬上介质。
  • 两个极限公式(计算题):
    • 奈奎斯特(无噪声):C = 2W·log₂V(W 为带宽 Hz,V 为每码元离散电平数)。
    • 香农(有噪声):C = W·log₂(1 + S/N)。注意信噪比常以分贝给出:dB = 10·log₁₀(S/N),30 dB 即 S/N = 1000。
  • 传输介质:双绞线(百米级,以太网主流)、同轴电缆、光纤(带宽大、衰减小、抗电磁干扰,长途骨干)、无线电/微波/卫星(广播式,易受干扰)。

6无线网络:802.11 要点

  • 无线链路的特殊性:信号衰减快、多径传播、易受干扰,且无法边发边听(自己的发送功率淹没接收),还有隐藏终端问题(A、C 都听不到对方却同时向 B 发送)——所以碰撞检测不可行,改用碰撞避免 CSMA/CA。
  • CSMA/CA:信道空闲等 DIFS 后发送;信道忙则先退避(倒计时在信道空闲时才递减);由于无法检测碰撞,每个数据帧都需要接收方回 ACK,没等到就重传。可选 RTS/CTS 短帧预约信道,专治隐藏终端:B 广播的 CTS 让 C 闭嘴。
  • 基础设施模式:AP + 基本服务集 BSS;AP 周期广播信标帧(含 SSID),主机扫描、关联后才经 AP 收发。802.11 帧有三个地址常考:接收方 MAC、发送方 MAC、以及 AP 与有线网互联所需的路由器/目的 MAC。
  • 移动性:蜂窝网/移动 IP 用「本地代理 + 转交地址 + 隧道」让移动主机保持可达,原理与 4G/5G 核心网锚点一致。

7网络安全:加密体系与 TLS

  • 四大目标:机密性、报文完整性、端点鉴别、不可否认。
  • 对称加密(AES):同一密钥加解密,快,但有密钥分发难题。公钥加密(RSA、ECC):公钥加密、私钥解密,慢约千倍。实践永远是混合:公钥体制协商出对称会话密钥,数据用对称加密。
  • 报文完整性:密码散列(SHA-256)+ 共享秘密 → MAC(报文鉴别码,如 HMAC)。数字签名:用私钥对报文散列加密,任何人用公钥验证——同时提供完整性、鉴别与不可否认。
  • 证书与 CA:解决「这个公钥真是这个网站的吗」。CA 用自己的私钥给「域名 + 公钥」签名成证书;浏览器内置根 CA 公钥,沿信任链验证。
  • TLS 握手(HTTPS = HTTP over TLS):客户端发支持的算法 + 随机数 → 服务器回选定算法 + 证书 + 随机数 → 客户端验证证书、通过密钥交换(现代用 ECDHE,提供前向保密)算出共享主密钥 → 双方派生会话密钥,此后全部对称加密 + MAC。TLS 1.3 把握手压到 1 RTT。
  • 常考攻击一句话:嗅探(交换网络中用 ARP 欺骗实现中间人)、IP 欺骗、SYN 洪泛(DoS)、DDoS(僵尸网络)、DNS 缓存投毒。防火墙按规则过滤分组;IDS 深度检测报文内容。

8全链路串讲:从输入 URL 到页面渲染

这是把五层串成一条线的终极题,也是理解全书的试金石。设主机刚接入网络,在浏览器输入 http://www.example.com:

  1. 获取网络配置(DHCP)App:主机广播 DHCP Discover(UDP 68→67,IP 源 0.0.0.0、目的 255.255.255.255,以太网广播帧),经 Offer/Request/ACK 拿到:自己的 IP、子网掩码、默认网关 IP、本地 DNS 服务器 IP。
  2. 找到网关的 MAC(ARP)Link:DNS 服务器不在本子网,数据要发给默认网关。主机广播 ARP 请求网关 IP,网关单播回其 MAC,缓存之。
  3. 域名解析(DNS)App:先查本机/浏览器缓存;未命中则向本地 DNS 服务器发 UDP 53 查询(递归),本地 DNS 依次迭代查询根 → .com TLD → example.com 权威服务器,拿到 A 记录,层层缓存后返回 IP。
  4. 建立 TCP 连接Transport:主机以随机临时端口向服务器 80 端口三次握手(SYN → SYN+ACK → ACK)。若是 HTTPS,再叠加 TLS 握手协商会话密钥。
  5. 逐跳转发Net:每个 TCP 段封装成 IP 数据报。若主机在内网,出口处 NAT 改写源 IP:端口并记表。每台路由器最长前缀匹配查转发表选下一跳(转发表由 OSPF/BGP 事先算好),TTL 减 1、重算首部校验和、重新封装链路层帧(MAC 换成本跳两端),源/目的 IP 不变。
  6. 请求与响应(HTTP)App:发送 GET / HTTP/1.1(带 Host、Cookie 等首部);服务器(或 CDN 边缘节点、或命中的 Web 缓存)回 200 OK + HTML。传输过程中 TCP 负责按序重组、丢包重传,拥塞窗口从慢启动逐渐张开;接收窗口防止压垮浏览器。
  7. 渲染与后续:浏览器解析 HTML,对其中每个图片/脚本对象在持续连接上继续发 GET(HTTP/2 则多路复用并发取)。连接空闲后四次挥手关闭,主动关闭方进 TIME_WAIT。
一句话总结整门课 DNS 把名字换成地址,TCP 把不可靠网络包装成可靠管道,IP 把数据报逐跳路由到目的主机,ARP 和以太网把每一跳落实为一次链路层交付,物理层把它变成信号。每层只依赖下层的服务、只对上层负责——这就是分层的全部含义。

9.3 计算题清单(逐个过一遍)

  1. 时延:分清传输 L/R 与传播 d/s;存储转发多跳累加;流水线传输总时延 = 首个分组到达时间 + (N−1)·L/R。
  2. 停等利用率 / 窗口:U = (L/R)/(RTT + L/R);要打满链路,窗口 ≥ 时延带宽积 + 1 个帧。
  3. 子网划分:给 /x 求掩码、网络地址、广播地址、可用主机数;给主机数需求反推前缀;路由聚合与最长前缀匹配判转发出口。
  4. IP 分片:片数 = ⌈数据长 / (MTU−20 取 8 的倍数)⌉;写出每片的长度、MF、偏移(÷8)。
  5. TCP 序号:ack = 已按序收到的最后字节 + 1;第二段序号 = 第一段序号 + 第一段数据长度。
  6. 拥塞窗口演化:给 ssthresh 与丢包事件,逐 RTT 列 cwnd(慢启动翻倍、拥塞避免加一、超时归 1、3 冗余 ACK 腰斩)。
  7. RTT 估计:代公式 EstimatedRTT、DevRTT、Timeout = Est + 4·Dev。
  8. Dijkstra / DV 迭代表:按算法列表格逐步填,DV 注意链路变价后的重新通告。
  9. CRC:模 2 除法求余数;验证时余 0 为通过。
  10. 香农 / 奈奎斯特:注意 dB 换算与 log₂。
  11. DNS/HTTP 响应时间:累加各级 DNS 查询 RTT + TCP 握手 1 RTT + 每对象请求 RTT(区分非持续/持续/流水线)。

9.4 最容易写错的 10 个坑

  1. 传播时延与分组长度无关;传输时延与距离无关。
  2. DNS 主要用 UDP,但它是应用层协议;DHCP、RIP 同理(RIP 跑 UDP 520,OSPF 直接封装在 IP,BGP 跑 TCP)。
  3. TCP 的 ack 是「期望的下一个字节」,不是「已收到的最后字节」。
  4. 三次握手第三个 ACK 可以带数据;SYN/FIN 各占一个序号但不含数据。
  5. IP 首部校验和只覆盖首部且每跳重算;UDP/TCP 校验和覆盖伪首部 + 首部 + 数据。
  6. 分片在任何缺 MTU 的路由器都可能发生,重组只在目的主机。
  7. 可用主机数要减 2(网络地址与广播地址);/31、/30 点对点链路是例外考点。
  8. 交换机查不到目的 MAC 是泛洪,不是丢弃;路由器查不到路由才丢弃(或走默认路由)。
  9. 发往外网的帧,目的 MAC 是网关的,不是目的主机的。
  10. 快恢复后进入拥塞避免(线性),不是慢启动;只有超时才回 cwnd = 1。
